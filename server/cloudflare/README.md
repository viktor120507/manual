# Чат практикума на Cloudflare

Подготовлен Cloudflare Worker + **одна общая** Durable Object для всех страниц сайта. Посетитель выбирает имя и пишет сразу: аккаунт, пароль, email, GitHub и OAuth не требуются. Для владельца нужен один аккаунт Cloudflare. Никаких ключей владельца в браузере нет.

**Сервис размещён в Cloudflare на действующем тарифе Workers Free.** Адрес: https://pgk-praktikum-chat.pgk-praktikum-chat.workers.dev/api/chat. `assets/chat-config.js` подключает виджет ко всем страницам практикума через этот сервис. HTTPS, обмен сообщением между двумя анонимными SSE-сессиями и ограничения CORS проверены через публичный адрес. Версия Worker: `807dfb82-f928-41e1-b0cd-75c9b4eb5c3f`. Учётные данные Wrangler остаются вне репозитория. Сайт публикуется на GitHub Pages из ветки `main`; сервис Cloudflare развёртывается отдельно.

## Что хранится

- Только в памяти: до 200 сообщений, имена, временные анонимные токены, IP для ограничений частоты отправки.
- В постоянном хранилище: только время следующей очистки — одно значение alarm. Тексты, имена, токены и IP туда не записываются. SQLite binding нужен для доступности Durable Objects на бесплатном тарифе; пользовательские таблицы не создаются.
- Вся история очищается каждые 2 часа; серверная alarm срабатывает без посетителей. Перед запросом и каждые 15 секунд активного соединения также проверяется срок. В окне есть обратный отсчёт.
- После перезапуска/вытеснения объекта из памяти история исчезает раньше. Двухчасовой срок — верхняя граница хранения, а не гарантия сохранения на два часа.
- Тело сообщения максимум 800 символов, тело запроса максимум 4 КБ. История в браузере также ограничена 200 сообщениями.
- Присутствие: подключённые посетители с живым SSE-соединением. Браузер подтверждает присутствие примерно раз в 30 секунд. При закрытии вкладки отправляется leave; если он не дошёл, участник исключается после 90 секунд без подтверждения и следующей проверки (до 15 секунд). Потоки отключаются при переполнении очереди 64 КБ.
- Максимум 60 соединений, 20 на IP и 500 сессий. Неактивные сессии удаляются через 30 минут. Счётчики ограничений максимум 2000 и очищаются. Лимиты отправки: 8/10 секунд на посетителя, 60/10 секунд на IP, 120/минуту на всю комнату.
- Сообщения выводятся как текст. HTML и скрипты не выполняются. История не записывается в localStorage/sessionStorage и не отправляется в логи приложения. Cloudflare observability выключена в конфигурации.

Cloudflare может вести собственные технические метаданные/журналы инфраструктуры. Скопированный текст, скриншоты и содержимое полностью зависшей/офлайн-вкладки не удаляются серверной очисткой. Это публичный общий чат, не личная переписка.

## Локальная проверка

Нужен Node.js 22+ и pnpm. Из этой папки:

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm dev
```

Эмулятор слушает только `127.0.0.1:8781`, ничего не публикует. Чтобы сайт http://127.0.0.1:8780/ и предпросмотр на 8776 подключались к эмулятору, выполните `node set-endpoint.mjs --reset`. Сейчас общий файл настройки указывает на размещённый сервис. Внешний Cloudflare аккаунт для локального режима не нужен. Сайт обслуживает `node server/chat-server.mjs` из корня проекта.

При работающем эмуляторе `pnpm test:runtime` проверяет два одновременных анонимных подключения, доставку сообщения через настоящий Workers runtime, CORS и выход. `pnpm test` дополнительно проверяет двухчасовую alarm на управляемых часах, границы тела запроса, лимит истории, частоту отправки, общую комнату, защиту IP-заголовков, очистку ушедших участников и отсутствие восстановления текстов из хранилища.

Проверка размещённого сервиса: `CHAT_TEST_ENDPOINT=https://pgk-praktikum-chat.pgk-praktikum-chat.workers.dev/api/chat pnpm test:runtime`. Проверка отправляет одно явно помеченное тестовое сообщение, которое исчезает при общей очистке истории.

Ограниченный нагрузочный тест: `CHAT_TEST_ENDPOINT=https://pgk-praktikum-chat.pgk-praktikum-chat.workers.dev/api/chat pnpm test:load`. Создаёт 15, затем 20 независимых анонимных SSE-сессий, отправляет 55 помеченных тестовых сообщений тремя одновременными волнами, проверяет 1025 доставок, heartbeat, восстановление истории после переподключения и выход всех тестовых участников. Имена и сообщения теста исчезнут при общей очистке. Токены в отчёт не записываются. Максимум соединений с одного IP — 20, поэтому при проведении теста закройте свой локальный виджет, если он использует тот же адрес. Если нужно учесть уже открытую вкладку, `CHAT_TEST_PEERS=19` создаст 19 тестовых участников.

Результат 9 октября 2026: полный тест через публичный сервис за 69 секунд прошёл. 20 независимых сессий/потоков по HTTP/2 через одно TLS-соединение, 55 сообщений, 1025/1025 доставок; медиана 133,9 мс, p95 230,1 мс, максимум 332,8 мс. HTTP-ошибок и обрывов в этом прогоне нет. Каждый участник получил 4 heartbeat, история из 55 тестовых сообщений восстановилась после переподключения, после выхода всех счётчик онлайн — 0. Два предыдущих прогона через отдельные HTTP/1.1/TLS-соединения из этого компьютера прерывались сетевыми ошибками (в диагностированном прогоне ECONNRESET); причину сети окончательно не установили. Это функциональный тест сервиса с виртуальными участниками, не проверка 20 физических устройств/сетей, длительной работы или нагрузки интерфейса на телефонах. Настройки и код размещённого Worker во время теста не менялись.

## Подключение после входа владельца и разрешения на размещение

1. Владелец входит в свой Cloudflare аккаунт и авторизует Wrangler. Пароли, API-токены и секреты не передавать в чат и не записывать в репозиторий. Создание нового аккаунта и принятие условий выполняет владелец.
2. `pnpm exec wrangler whoami` — проверить доступ. `pnpm exec wrangler deploy --dry-run` — проверить сборку без размещения.
3. Разместить **только сервис чата**, командой `pnpm deploy`, на Workers Free; не включать платный тариф автоматически. Сервис получит собственный HTTPS workers.dev URL, DNS сайта менять не требуется.
4. Проверить `/api/chat/health` по возвращённому адресу. Настройки разрешают запросы только с `https://pgk-mdk.ru`, `https://www.pgk-mdk.ru` и двух локальных предпросмотров. Если адрес сайта меняется — изменить ALLOWED_ORIGINS.
5. В этой папке выполнить `node set-endpoint.mjs https://pgk-praktikum-chat.<account>.workers.dev`. Это меняет только публичный адрес в локальном `assets/chat-config.js`, ничего не публикует. На всех 37 страницах уже подключён общий файл настройки. Для отключения: `node set-endpoint.mjs --reset`.
6. Проверить локальный сайт с размещённым сервисом, затем отдельно публиковать сайт на GitHub Pages **только после разрешения пользователя**. При публикации обновить версию URL chat-config.js для сброса старого кэша.

Нельзя считать настройку законченной, пока нет действующего HTTPS URL и проверки двух пользователей через него. Локальный эмулятор — проверка совместимости, не размещённый сервис.

## Тариф и ограничения

У Cloudflare есть Workers Free + SQLite-backed Durable Objects. По текущей документации DO включает 100 000 запросов/день и 13 000 GB-секунд/день. Активный SSE держит один объект в памяти; 24 часа при учёте 128 MB — приблизительно 11 059 GB-секунд/день, независимо от числа посетителей одной комнаты. Это ориентир, а не гарантия бесплатности или доступности; другие Workers, злоупотребления и лимиты платформы также учитываются. На Free превышение лимита приводит к отказам, а не к автоматическому включению платного тарифа. Не создавать отдельный объект на каждую страницу/посетителя.
